Welcome to the issue triage guide. This page aims to help contributors get started with triaging issues (bugs and features that have not yet been investigated).

There are two types of triage queue:
- [Bugs](https://github.com/deskflow/deskflow/issues?q=is%3Aissue%20state%3Aopen%20type%3A%22Triage%20%5Bbug%5D%22)
- [Features](https://github.com/deskflow/deskflow/issues?q=is%3Aissue%20state%3Aopen%20type%3A%22Triage%20%5Bfeature%5D%22)

# General

1. Close or archive issues that are stale, duplicates, or out of scope.
1. Ensure the issue has a clear title and detailed description.

# Bugs

1. The first and most basic step is to try and reproduce the bug. If you can reproduce the bug, then this makes things simple; post a comment on the issue saying you're able to reproduce it. When more than one person can reproduce a bug, this goes a long way to getting the bug out of triage.
2. Next, try to improve the 'Steps to reproduce' by simplifying and clarifying them, removing any unnecessary steps. The aim is to get the 'Steps to reproduce' as short as possible while still reproducing the bug.
3. If you are unable to reproduce, then ask the reporter for more details (for example, logs at debug level).
4. Some bugs are intermittent or rarely happen, and we need to ensure that this is highlighted on the bug report.

# Features

1. If you believe it is in-scope for the product and is possible, then please add a comment saying so.
